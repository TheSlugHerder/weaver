Project:
	To use current existing Dungeons & Dragons digital tools as services in a core that passes natural language user game instructions (text adventure-like) to competent AI models with a collection of in-game location relevant obejct and instruction identifiers, where the AI will reply with keyword instructions matched with natural user language (supplied) and extrapolated as matching keyword instructions, thereby simplifying the understanding of user/player instructions to the game engine. By providing the AI with a restrictive set of keyword instructions, object names, etc., the aim here is to only use the AI as a translator-like assistant without daydream, hallucination, or forgetfulness. (suggest)
	A narrator role will also be used for a second AI request by taking the resulting actions of player in-game room/environment exploration, interaction, etc., where the AI will be requested to expand upon the game's backend results (die rolls, monster actions/responses, player actions/results, object interactions and results (trap sprung, player dodged spike, etc.) in a more story-like lingual way - a narrator. (suggest)
	The backend of the game will be set around dnd-5e-core python package linked to a document database, both of Json data structures. User accounts will also be stored in the same data/document-base (mongodb, etc.) (suggest)
	Playing a game will require some kind of room/location/environment map data structure, and for this a Json structure of locations, objects, monster spawn points, traps, doors, room dimensions, etc., (other location data for non-dungeon locations) including entrance/exits, linked pathways, etc., to other rooms/locations. (suggest)
	The game should be multiplayer with the option to allow other players to join game, or ignore requests, etc., typical of multiplayer gaming. (suggest)
	Player data will also include game ID (for multiplayer and map location), character items, d&d character and game data, etc. (suggest)
	A reverse proxy is to be implemented. (suggest)
	The game will be presented via Web Browsers which will display map, player/team locations, fog of war, discovered areas and objects, as well as discovered/killed monsters, discovered objects/traps, etc. (suggest)
	A security system for the game will be used (suggest)

Expanded Stack Components
OS & Host Security:
	Ubuntu Server 24.04 LTS, ufw, fail2ban, etc.:
		Host environment. ufw blocks all ports except 80/443; fail2ban bans brute-force SSH/HTTP abusers.

Edge Web Server:
	Nginx (Reverse Proxy) + Certbot:
		Handles HTTPS certificate renewal, security headers (HSTS, CSP, CORS), and transparent Upgrade routing for WebSockets.

Optional Apache Role:
	Apache2 (or Nginx standalone):
		If running existing Apache virtual hosts, Apache acts as the internal web proxy while Nginx sits at port 443 handling SSL and WebSocket multiplexing.

App Server & Runtime:
	Python 3.12+, FastAPI, Uvicorn (uvloop, httptools):
		High-concurrency ASGI server managing REST routes, background tasks, and persistent WebSocket game rooms.

Game Rules Engine:
	dnd-5e-core:
		Complete 5e combat resolver, character stats, condition flags, and bundled SRD JSON datasets.

Auth & Access Control:
	fastapi-users[beanie], pwdlib[argon2], python-jose:
		Production-grade JWT/Cookie multi-account management [user registration, password hashing (Argon2id), email verification, and RBAC (DM vs Player roles).]

Database & ODM:
	MongoDB Community 7.0+, beanie, motor:
		Document database for campaigns, keyed rooms, item definitions, and account profiles with async object-document mapping.

AI LLM Interface:
	openai (Async) or instructor:
		Communicates with the external 8B endpoint (Groq, Together, DeepSeek) for zero-CPU serverless intent parsing and streamed narration.

Frontend UI:
	Tailwind CSS, HTML5 Canvas / Pixi.js, Vanilla JS / Alpine.js:
		Tailwind: Responsive character sheets, dark-mode DM screens, turn order HUD.
		Canvas / Pixi.js: Renders the 2D grid map, player tokens, line-of-sight, and fog of war directly in browser.
